# T211 — loopd_orphan_reaper Sandbox::new() must filter scripts/ copies to regular files

check: export CARGO_TARGET_DIR=/Users/jadams/workspace/chug/target-shared; touch src/*.rs tests/*.rs; cargo test --test loopd_orphan_reaper

## Repo context

`tests/loopd_orphan_reaper.rs` `Sandbox::new()` (~line 356) copies EVERY
entry of the checkout's `scripts/` dir into the sandbox:

```rust
for entry in fs::read_dir(repo_root().join("scripts")).expect("scripts dir") {
    let entry = entry.expect("scripts entry");
    fs::copy(entry.path(), scripts.join(entry.file_name())).expect("copy script");
}
```

`fs::copy` on a directory fails with "the source path is neither a regular
file nor a symlink to a regular file". Cycle-95 evidence: the T208 child's
`scripts/__pycache__/` (python bytecode cache, regenerated by any
`py_compile` run) sat UNTRACKED in its worktree and turned
`a_failing_driver_probe_means_no_sweep`,
`the_reaper_terms_an_orphan_through_loopd_before_the_build`, and
`the_cwd_leg_identifies_an_orphan_through_loopd` RED in 0.2–0.3s (panic at
the copy, line 360) — 3 of 20 family tests dead from build litter, with the
suite otherwise green (removing the litter → 20/20). Python now lives in
`scripts/` (T208's distill_experiment.py), so `__pycache__` will keep
reappearing in any checkout that byte-compiles — this flake class recurs by
construction.

estimate: ~25 changed lines (tests/loopd_orphan_reaper.rs only).

## Requirements

1. The copy loop skips any entry that is not a regular file (filter via
   `entry.file_type()` — `is_file()` passes, directories/symlinks-to-dirs/
   fifos skip; a symlink TO A REGULAR FILE may copy or skip, editor's pick,
   named in a comment).
2. A comment names the cycle-95 `__pycache__` incident class.
3. RED-proof: a new sibling test (or a leg in an existing sandbox test)
   creates a junk DIRECTORY inside a scratch `scripts/` source and asserts
   the filtered copy skips it while regular scripts still copy — the test
   fails if the filter is removed (mutant: delete the filter → the junk
   dir panics the copy again).
